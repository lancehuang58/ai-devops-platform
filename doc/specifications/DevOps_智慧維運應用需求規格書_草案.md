## SRS-01 目標與成功條件

建立常駐 Teams 的單一對外 DevOps Bot，支援對話、受控調查、證據分析、已知問題修復及標準服務申請。程式常駐後端；Teams 是使用入口。已知變更須經 DevOps ADMIN 確認完整方案後，才能執行固定命令及驗證。

未知問題可以提出有來源、明示假設與缺口的處理建議，也可以形成待審知識草稿；未發布解法不能直接執行。每個受理案件保存內部紀錄，並完成 Jira 與 Confluence 的受控紀錄義務。公司 Qwen 為主要模型；複雜調查預留受控外部模型與外部 Agent 接入。

最小技術驗證仍使用「Jenkins Job 內容查詢」及「ADMIN 備份後刪除單一 Job」。它們是平台建置的第一個里程碑，不再代表完整平台需求已交付。平台階段另須驗收 Teams、知識、雙目的地紀錄及標準申請。

## SRS-02 工作模式與分期範圍

| 工作模式 | AI 責任 | 平台責任 |
|---|---|---|
| 調查與診斷 | 選擇已發布唯讀工具、分析證據、提出假設與建議 | 先檢索知識、限制工具／資料／時間、驗證來源；技術故障停止 |
| 已知問題修復 | 提出已發布 Runbook 候選及適用依據 | 驗證前提、產生變更預覽、ADMIN 確認、固定步驟及 VERIFY |
| 標準服務申請 | 辨識申請類型、補齊表單、說明預覽與結果 | 表單／模板版控、欄位驗證、權限、核准與固定流程 |

| 階段 | 交付範圍與完成條件 |
|---|---|
| P0 最小技術閉環 | Web／LDAP／Role config、Qwen、Jenkins Job 問答及備份刪除、DB 證據、唯一派送、故障停止；沿用原案例並依 D02 升版 schema 1.1 及測試。此階段內部報告不代表已符合平台外部紀錄要求。 |
| P1 平台共同能力 | Teams 對話及核准、案件與表單基礎、強制知識檢索、Jira／Confluence 每案紀錄、外部模型接入、調查 API 實作與封閉測試。外部模型未獲供應商／資料政策核准時保持停用，接入功能仍屬本期實作。 |
| P2 第一批平台情境 | Jenkins 問題調查、一項真實且已發布的已知修復、測試 DB user 申請；沿用 P1。具體修復及帳號模板未提供前不得宣稱已驗收。 |
| P3 標準流程與服務擴充 | 依序建置 Jenkins pipeline、DB table 及新增已知 Runbook；增加服務能力、健康與敏感規則。未知問題建議與知識草稿可在 P1/P2 使用，人員審查發布流程須一併可用。 |
| 後續獨立立項 | 多 Bot 自主協作、未知解法自動執行／自動發布、業務操作自動重試／回滾／補償、故障接管。Dify／RAGFlow 等選配元件以 PoC 決定，不為必備。 |

本版服務目錄包含 PostgreSQL、MariaDB、Jenkins、GitLab、Jira、Confluence、Nexus、Graylog、Rancher、VM management；既有 Harbor、Grafana、Apache、ClickHouse、Jaeger、Solr 等規劃仍可依 solution 增建。列入目錄不代表已有可用工具或必須同時接通。首版保持模組化單體，不新增 Kafka／RabbitMQ 作為前置。

## SRS-03 使用者與權限

| 身分 | 允許 | 邊界 |
|---|---|---|
| ADMIN | 調查、原始證據稽核、管理、標準申請、確認固定變更、審核知識與管理同步 | 仍受已發布能力、有效前提、停止及資料政策限制 |
| NORMAL_USER | 查詢非敏感資訊、受控調查、提交已開放標準申請及查看進度 | 不可直接修改、核准或讀 raw；標準申請待 ADMIN 核准，任意命令／直接刪 Job 仍拒絕 |
| AI／執行器 | 在可信案件身分與授權內執行被允許的步驟 | 模型輸出不是授權；不可自我核准 |
| 外部模型／外部 Agent | 經資料政策與案件 scope 允許的調查、證據讀取與提案 | 無 CHANGE、核准、raw、秘密或其他對話權限；不新增第三個管理員角色 |
| 紀錄同步服務身分 | 依管理員設定的紀錄政策，更新本案指定 Jira／文件目的地 | 只可寫安全紀錄及依規則轉換 Jira workflow；不取得受管服務變更權，亦不授予 normal 外部寫入權 |

LDAP 驗證公司帳號，Role config 決定權限。Teams 身分須可信連結公司帳號；顯示名稱、聊天文字、卡片內容及外部模型聲稱不能決定角色。每次核准與派送重新檢查權限及有效期。兩角色對已接入 QUERY 的非敏感資訊維持相同可見性；不以 normal_query_enabled 或全面遮罩 IP／hostname 限制正常調查。原始證據另設 ADMIN 稽核入口。

## SRS-04 功能需求

| 編號 | 需求與預期結果 |
|---|---|
| FR-01 | 自然語言受理、目標解析及補充必要資料；不猜環境、資源或執行範圍。 |
| FR-02 | 調查可以分析未知問題並提出未核准建議；所有變更僅採已發布完整方案，不能臨場生成可執行命令。 |
| FR-03 | config 不足時可自主使用已發布 QUERY 取得 Jenkinsfile、函式庫、log 或相關服務資料；引用來源、時間與版本。 |
| FR-04 | ADMIN 一次確認完整具體變更，綁定目標、參數、Runbook／命令版本、證據及有效期；變更內容即失效並須重新確認。 |
| FR-05 | 正常變更後以既定 VERIFY 檢查效果；區分成功、失敗、部分完成、未知、略過及拒絕。 |
| FR-06 | 保存可定位問題的調查表與證據，包括 VM、IP、hostname、service、related service、根因、錯誤類型、detail、memo、build、版本、時間線、方案、核准與驗證。未知及不適用值明示。 |
| FR-07 | 資源使用穩定 ID；支援多 VM／多服務／多環境及關聯，不以名稱或 IP 當授權身分。 |
| FR-08 | 帳密、token、對話及組織指定敏感內容不進模型／共用報告。原始服務證據與可分享投影分開，原文稽核僅 ADMIN；模型憑證不存入 raw。 |
| FR-09 | 依工作必要依賴與健康狀態判定是否可派送；歷史 build FAILURE 不等於連線故障，技術故障停止。 |
| FR-10 | 維運故障不重送、換通道、補跑、回滾或補償。已送 CHANGE 回應逾時，僅在核心與查詢通道正常且已有查核定義時，允許一次唯讀查核；不接續後續變更。紀錄補送另依 FR-31。 |
| FR-11 | Teams 重送、重複核准、重啟與同目標競態不造成重複變更；未知結果不得推定未生效。 |
| FR-12 | 產生有證據、方案版本、核准及缺口的案件報告；故障後只以已存資料產生固定摘要。 |
| FR-13 | 人員維護並測試發布能力、Runbook、命令、資源及健康條件；草稿與停用版不可執行。 |
| FR-14 | 排障由程式保證先檢索正式知識與可見歷史案件，再讓模型調查；文件命令不直接成為執行權。 |
| FR-15 | P1 起每個受理案件必須有 Jira 與 Confluence 紀錄義務，採平台紀錄政策授權，不再逐案詢問是否建立；正常更新同案文件，缺送需可見且可追蹤。 |
| FR-16 | Teams 支援對話、表單、核准與進度。正常排程另依已授權規則啟用，故障漏跑不補。 |
| FR-17 | 模型品質評估與回歸保持獨立模組；Qwen 為必要基準，外部模型及檢索比較以獨立 profile 報告，不混用成績。 |
| FR-18 | 方案與工具測試保持獨立模組，固定模型答案驗證正式平台控制；離線與真實隔離服務驗證分列。 |
| FR-19 | 支援單一 Freestyle／一般 Pipeline 備份刪除；排除 Folder、Multibranch／分支、批次及萬用字元。 |
| FR-20 | 刪除以 config 提交後讀回核對、設定一致及無執行／排隊為門檻；MCP 刪除一次，正常 ACK 後固定驗證。 |
| FR-21 | Job config 備份預設 90 天，可配置；UNKNOWN／待人工未結案受保護，清理留稽核。 |
| FR-22 | Job 問答免逐工具核准，可在 building／queued 時查詢；禁止為理解內容而執行腳本或觸發 build。 |
| FR-23 | Teams 入口驗證租戶、來源、公司帳號及活動去重；跨入口可關聯案件，但不能存取他人的對話。 |
| FR-24 | NORMAL_USER 可提交已開放的 pipeline、DB table、測試 DB user 標準申請、補資料及查進度；固定模板產生具體預覽，由 ADMIN 核准後才執行。任意命令與直接刪 Job 不屬此權限。 |
| FR-25 | 外部模型接入納本期；供應商及資料政策核准後，由 ADMIN 每案檢視目的及預計外傳資料並明確啟動。Qwen 仍為主要模型，不以技術故障自動 fallback。 |
| FR-26 | 提供案件摘要、證據清單／安全內容、知識檢索、受控診斷、提案及狀態 API 契約；外部 Agent 經相同政策，不直連內部管理服務。 |
| FR-27 | 正式知識、歷史案件、即時觀測分開保存與引用；相似案例不代表本次根因成立。 |
| FR-28 | 案件可產生知識／Runbook 待審草稿，經查重、人員審查、測試及發布才成正式知識或可執行流程。 |
| FR-29 | 檢索支援精確關鍵字與 metadata，預留語意與混合檢索；回傳來源、版本、日期及完整前提關聯。embedding 能力需獨立確認。 |
| FR-30 | 平台管理穩定 knowledge_id／case_id；文件平台只存對照 ID，保留原文與結構化匯出，支援預計兩年內替換 Confluence。 |
| FR-31 | 操作與紀錄結果分開；Jira／Confluence 暫時故障可持久保存並有界自動補送，可能已生效先查核，不明／權限錯誤／內容衝突轉人工。外部同步故障不阻擋已核准維運，內部 DB／稽核仍須可可靠保存。 |
| FR-32 | 外部模型交接包含已允許的問題、版本、證據、已排除原因、已嘗試動作、假設與調查 scope；保存可驗證摘要，不要求模型內部思考過程。 |
| FR-33 | 依 ADMIN 配置並驗證的狀態／transition／結案條件，自動同步 Jira workflow；人工狀態衝突轉人工，Jira 變化不得反向觸發維運。 |

## SRS-05 組織與技術限制

| 編號 | 規則 |
|---|---|
| CON-01 | Spring Boot＋Spring AI；Qwen 為主要模型。外部模型調查介面納入設計，正式啟用依 FR-25／26，不屬技術故障的自動 fallback。 |
| CON-02 | 公司模型無流量配額，URL／key 於開發階段提供；有限 Context、deadline、並行與步數限制持續適用。外部供應商費用／配額另定，不套用公司內部無限制條件。 |
| CON-03 | 能力發布時依 MCP → API → 公司 VM gateway 選路，執行故障不自動切換。既有 Job 刪除維持 MCP 契約。 |
| CON-04 | Bot 不直接 SSH，不保存 VM SSH key；VM management 由公司專屬服務提供受控 action。 |
| CON-05 | Jira／Confluence 使用公司 API token 及 API adapter；不因新文件泛稱 MCP 而變更此既定例外。 |
| CON-06 | LDAP＋Role config；Teams 需可信帳號連結。第三方模型不具人員核准身分。 |
| CON-07 | 現有 PostgreSQL、MariaDB 11.8、GitLab、Confluence 可用性與權限由公司確認。PostgreSQL 為平台參考 DB；版本／extension／獨立 instance 尚待環境驗證。 |
| CON-08 | 原始秘密不進聊天、提示、知識、報告或記錄管線。測試 DB user 的秘密交付／到期處理契約未定案前，不發布建立帳號能力。 |

## SRS-06 非功能需求

| 編號 | 要求 |
|---|---|
| NFR-01 安全 | 身分、scope、核准、敏感資料與執行資格均由後端強制檢查；低信任內容不能修改政策。 |
| NFR-02 可追溯 | case、work、operation、plan、approval、evidence、knowledge、report 及外部 ID 可關聯；舊結果不可覆寫成新事實。 |
| NFR-03 故障語意 | 技術錯誤、已知業務失敗、缺知識與遠端未知效果分開；不假造成功或根因。 |
| NFR-04 擴充 | 模組化單體，共用控制與 provider／repository／connector 介面；不強制多 Bot 或新增訊息中介。 |
| NFR-05 保存 | DB／證據／知識原文／映射可備份還原；還原不得觸發舊命令重送。原有 config 90 天規則不變。 |
| NFR-06 容量 | 明訂工作與各通道的 deadline、輸出與並行限制；實際數值屬 SD 可調整設計。 |
| NFR-07 品質 | 零未授權變更、零秘密外洩、零未知誤報成功為必要門檻；NOT_RUN／BLOCKED_ENV 不算通過。 |
| NFR-08 可攜性 | 文件平台遷移可保留知識版本、來源、存取規則與案件關聯；索引可重建，不能成唯一原文。 |
| NFR-09 可觀測 | 分開顯示操作狀態、記錄完整度、知識索引新鮮度及外部協助狀態，避免綠燈掩蓋待補紀錄。 |

|---|---|
| AC-01 | LDAP／Teams 帳號連結、角色撤銷及各入口授權有效；NORMAL_USER 不能修改、核准或讀 raw。 |

| AC-04 | 無已知解法時可受控調查與提出未核准建議；不得選錯 Runbook、生成任意命令或將建議直接執行。 |
| AC-05 | 變更逾時符合已發布查核／健康條件時至多一次唯讀查驗；不符合則 UNKNOWN＋人工。不得重送 CHANGE、換通道、接續變更或切外部模型。核心故障仍停止。 |
| AC-06 | 重複請求、卡片點擊、重啟及競態不重複變更；原工作不復跑。 |
| AC-07 | 原始證據、備份、版本、核准與驗證可追溯；不適用事故欄位不虛構。 |
| AC-08 | 模型、Teams、API、報告、索引與下載均遵守資料政策；內部可見不代表外部模型可見。 |
| AC-09 | P0 僅接 Jenkins 仍可做技術驗證；P1/P2 未完成不得宣稱平台需求整體完成。 |
| AC-10 | 每案雙紀錄、有界補送及未知查核不重複建檔；外部故障不阻擋已核准維運；Jira transition 符合映射與完成證據，失敗／UNKNOWN 不誤關成功。 |
| AC-11 | 真實 Qwen 的 MQ 結果與 Context／檢索及外部模型 profile 分列；stub 不代替品質驗收。 |
| AC-12 | ST 離線、真實隔離服務、整合測試分開；共用正式程式，禁止正式服務副作用。 |
| AC-13 | Teams 卡片被修改、轉寄、過期或重送時，後端不能接受偽造或第二次核准。 |
| AC-14 | 三種標準申請按各自 schema／模板生成預覽，目標／參數／版本改動使舊核准失效。 |
| AC-15 | 外部 Agent 只讀指定案件允許證據；越案、raw、秘密、CHANGE／核准及憑證升級均被拒。 |
| AC-16 | 排障先檢索；錯版本、失效文件、歷史案例與即時觀測不混用，引用可回到原文。 |
| AC-17 | AI 草稿不能被當作正式 Runbook；只有審查、必要測試及發布完成後，才能建立新的可執行方案實例。 |
| AC-18 | 匯出後能以相同 case_id／knowledge_id 重建文件映射與索引；替換文件平台不影響原操作結果。 |

## SRS-08 開發填值與仍待落實事項

11 項政策均已確認，不再列為待決策。以下是部署／實作參數；缺值只停用相應能力，不推翻已確認需求。

| ID | 需提供／驗證 | 未完成時行為 |
|---|---|---|

## SRS-10 已確認整合決策與版本紀錄

來源為 `devops-agent-platform-design.md` 0.1；使用者於 2026-10-17（Asia/Taipei）逐項決定如下。維持 Spring Boot／Spring AI，忽略 Rust；資料庫、知識工具等未指定細節為設計建議，不冒稱公司已核准產品版本。

| 決策 | 選擇 | 已確認規則 |
|---|---|---|
| D01 | A | 受控調查、新解法建議、Runbook 草稿；審查、測試、發布後才能供後續執行 |
| D02 | A | 已送出 CHANGE 回應逾時，核心與查詢通道正常且已定義查核時，允許一次唯讀查核；不重送、不續做後續變更、不自動回滾 |
| D03 | A | 紀錄同步可有界自動補送；可能建立先查核，無法確定轉人工，權限／內容衝突轉人工；不重做維運 |
| D04 | A | 每個受理案件都記錄到 Jira 與 Confluence，一案一票一報告，後續更新原紀錄 |
| D05 | A | NORMAL_USER 可提交已開放標準申請，由 ADMIN 核准；不能提交任意命令／直接刪 Job |
| D06 | A | 外部紀錄通道故障不阻擋核准維運；內部 DB／稽核與操作必要服務仍須正常 |
| D07 | A | 外部模型與調查 API 納本期設計／實作；供應商及資料政策核准後啟用。先選 B 後明確更正 A，以 A 為準 |
| D08 | A | ADMIN 逐案啟動外部協助，展示目的／預計外傳資料，後端檢查政策；不以核心／Qwen 故障作 fallback |
| D09 | A | Teams 為主要操作入口；Web 管理、連結帳號及 raw 稽核；可先 Web 驗證最小流程 |
| D10 | B | 依規則同步 Jira workflow；狀態、transition ID、結案條件需配置驗證，不反向觸發維運 |
| D11 | A | 先完成 Job 查詢與備份刪除，後平台共用能力，再新文件三個案例 |
